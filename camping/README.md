# 캠핑장 예약 도구함

캠핑장 예약을 빠르게 시도하는 브라우저 도구 모음입니다.
GitHub Pages로 그대로 서빙됩니다. 진입점은 `index.html`.

| 도구 | 대상 | 형태 |
|---|---|---|
| `camfit.html` | [캠핏](https://camfit.co.kr) | 북마클릿 (사이트 위에 패널을 띄움) |
| `thankyou.html` | [땡큐캠핑](https://m.thankqcamping.com) | 스크립트 생성기 |
| `blueline.html` | [해운대 블루라인파크 스카이캡슐](https://www.tbluelinepark.com/ticket/GD2100036) | 북마클릿 (예매 페이지 위에 패널을 띄움) |

---

## 수정할 때 어디를 고치나

**이 부분만 기억하면 됩니다. 두 도구의 구조가 서로 다릅니다.**

### 캠핏 — `src/camfit-panel.js` 를 고치고 빌드

`camfit.html` 안의 북마클릿은 **빌드 산출물입니다. 직접 고치지 마세요.**
소스는 `src/camfit-panel.js` 하나뿐입니다.

```bash
# 1. src/camfit-panel.js 를 수정한 뒤
node build.js

# 2. 커밋 전 확인 (빌드를 잊었는지 검사)
node build.js --check
```

`build.js` 가 하는 일 — 주석·들여쓰기 제거 → `encodeURIComponent` →
`camfit.html` 의 `<a class="bm" href="javascript:...">` 와 복사용 `<textarea>` 에 주입 → 문법 검사.

### 스카이캡슐 — `blueline.html` 을 직접 고침

패널 코드는 파일 안의 `bluelinePanel()` 함수 하나입니다. 페이지가 열릴 때 이 함수의 소스로
북마클릿 링크를 만들므로 빌드가 없습니다. 고친 뒤 페이지를 새로고침해 다시 드래그하면 됩니다.

### 땡큐캠핑 — `thankyou.html` 을 직접 고침

로직이 파일 안의 `<script>` 에 그대로 들어 있습니다. 별도 소스도 빌드도 없습니다.

## 동작 방식

### 땡큐캠핑 — 오픈 시각에 맞춰 자동 시도

1. **서버 시계 동기화** — 응답의 `Date` 헤더로 PC 시계 오차를 보정합니다.
   왕복 지연의 절반을 더해 맞추므로, 로컬 시계가 틀려도 오픈 순간을 놓치지 않습니다.
2. **오픈까지 대기** — 긴 `setTimeout` 은 오차가 커서, 1초 전부터 20ms 간격으로 재확인합니다.
3. **우선순위대로 시도** — 지정한 사이트 순서대로 예약을 시도하고, 실패하면 다음 후보로.

### 캠핏 — 지금 실행 / 타이머 실행

헤더의 **서버 시간**을 보고 **지금 실행**을 누르면 그 순간 실행합니다.
타이머 날짜·시각을 정하고 **⏰ 타이머 실행**을 누르면 그 시각(서버 시간)에 같은 동작을 합니다.
("예약"은 캠핑장 예약에만 쓰고, 시각을 정해 두는 쪽은 "타이머"라고 부릅니다.)
기다리는 동안 헤더에 `실행까지 00:12:34` 가 표시되고, 앞 단계는 잠기며, **타이머 취소**로 취소할 수 있습니다.

**서버 시간 보정** — 캠핏 페이지와 같은 도메인(`camfit.co.kr`)에 약 1초마다 HEAD 요청을 보내 `Date` 헤더를 읽습니다.
(`api.camfit.co.kr` 은 다른 도메인이라 브라우저가 `Date` 헤더를 스크립트에 보여 주지 않습니다 — 예전 코드는 이 때문에
보정에 실패하고 PC 시계를 쓰고 있었습니다.) `Date` 는 초 단위라 한 번 재면 ±0.5초 오차지만, 잴 때마다
"서버-PC 차이가 들어갈 수 있는 범위"를 구해 최근 2분치를 겹치면 범위가 좁아집니다. 실제 캠핏에서 15회 만에 ±59ms 까지
줄었습니다. 헤더 배지에 `±50ms` 처럼 현재 오차가 보이고, 마우스를 올리면 PC 시계와의 차이가 나옵니다.
측정 간격은 0.85~1.15초로 흔듭니다(정확히 1초면 매번 초의 같은 지점을 재서 범위가 줄지 않습니다). 탭이 숨으면 쉽니다.

- 사이트 우선순위대로, 고른 금액으로 **사이트마다 한 번씩만** 보냅니다. 실패하면 다음 사이트로 넘어갑니다.
- 한 바퀴가 끝나면(성공·실패·타임아웃) 버튼이 **다시 시도**로 바뀌고, 다시 누르면 처음부터 한 바퀴 더 돕니다.
  저절로 재시도하지는 않습니다.
- 패널 로그에 요청 하나하나의 진행이 서버 시각(밀리초)과 함께 남습니다.
  `보안 토큰 확보` → `→ 요청 전송, 응답 대기 중` → `← HTTP 409 · 312ms — 실패: 사유` 순서입니다.
  기다리는 동안에는 헤더 배지에 `A-1 응답 대기 1.4초` 처럼 경과 시간이 표시됩니다.
- **10초** 안에 응답이 없으면 요청을 끊고 `⌛ 타임아웃` 으로 멈춥니다. 요청은 이미 서버에 닿았을 수 있어서
  다음 사이트로 넘어가지 않습니다(중복 예약 방지). 캠핏 예약 내역을 확인한 뒤 다시 누르세요.
  연결 자체가 실패한 경우(`✕ 요청 실패`)는 서버가 처리하지 않았다고 보고 다음 사이트로 넘어갑니다.
- **중지**를 누르면 기다리던 요청도 끊습니다. 이 경우도 서버에서 처리됐을 수 있습니다.
- "스크립트 복사"로 만든 콘솔 스크립트도 붙여넣는 즉시 실행되고, 같은 로그를 콘솔에 찍습니다.
  다시 시도는 `cfRun()`, 중지는 `stopCf()`.

금액은 **후보를 제안**만 합니다. 구역 요금표(`charges`·`tempCharges`·`peakPeriods`)로
주말 해석별 금액을 계산하고, 빈자리가 있으면 `calculate` 로 조회한 정확한 금액에 `추천` 표시를 붙입니다.
그중 **하나를 골라야** 실행됩니다(여러 금액을 동시에 보내지 않습니다).

## 캠핏 — Cloudflare Turnstile 토큰

캠핏 예약 페이지는 `/v1/book` 요청 본문의 `nonce` 에 Turnstile 토큰을 담습니다
(사이트 키 `0x4AAAAAAFI5jECJgKCLjsP7`, `action: "booking"`, `appearance: "interaction-only"`).
캠핑장 설정에 따라 서버가 토큰을 검사(enforce)하거나 기록만(observe) 합니다.

- 토큰은 **한 번 쓰면 끝**이고 약 5분 뒤 만료됩니다. 받은 지 **4분**이 지난 토큰은 쓰지 않고 미리 새로 받습니다(만료 직전에 보내지 않도록).
- 사이트 조회가 끝나 Step 3 이 열리면
  바로 위젯을 띄워 토큰을 받아 두고(만료되면 자동 갱신), 누를 때 선택한 사이트 수만큼(최대 6개)
  늘립니다. 쓴 위젯은 `reset` 해 다음 토큰을 받습니다. 준비 상태는 버튼 아래 `보안 토큰: 2/2 준비됨` 에 보입니다.
- 사람 확인이 필요하다고 판정되면 패널 아래(콘솔 스크립트는 화면 오른쪽 아래)에
  체크박스가 나타납니다. 직접 눌러야 합니다.
- 5초 안에 토큰을 못 받으면 사이트와 똑같이 `nonce` 없이 보냅니다.
  enforce 캠핑장에서는 이 요청이 거절될 수 있습니다.

## 캠핏 — 페이지에 맞춰 자동으로 열립니다

북마클릿을 누른 위치의 URL(`/camp/{캠핑장ID}/{구역ID}`)을 읽어 단계를 건너뜁니다.

| 누른 곳 | 열리는 화면 |
|---|---|
| 캠핑장 상세 `/camp/{캠핑장ID}` | Step 1 구역 선택 (캠핑장 선택됨) |
| 구역까지 `/camp/{캠핑장ID}/{구역ID}` | Step 2 날짜·사이트 (구역까지 선택됨) |
| 그 외 페이지 | Step 0 캠핑장 검색 |

URL 의 구역을 목록에서 찾지 못하면 Step 1 에서 직접 고르도록 안내합니다.

캠핑장 이름은 `/proxy/api/v1/app/experiences/camp/{캠핑장ID}` 로 확인합니다
(`/v1` 이 아닌 proxy 경로라 `api()` 헬퍼 대신 직접 호출). 실패하면 화면의
`og:title`·`h1`·`<title>` 과 구역 응답을 차례로 훑고, 그래도 못 찾으면
이름 없이 진행합니다 — 표시용이라 동작에는 영향이 없습니다.

## 스카이캡슐 — 사이트 함수를 그대로 씁니다

예매 페이지(maketicket)는 화면을 jQuery 전역 함수로 그립니다. 패널은 화면을 클릭하는 대신 그 함수를 부릅니다.

1. `chooseDate('YYYYMMDD')` → 서버가 회차 목록을 주면 사이트가 `getDateScheduleListAfter` 를 부릅니다.
   이 함수를 **한 번만 감싸서**, 원래 화면을 그린 직후 회차(`N회차(16:30 ~ 17:00)`)를 시작 시각으로 찾아 클릭합니다.
2. 회차를 누르면 같은 방식으로 `getDateSchedulePriceLevelListAfter` 뒤에 권종(`2인/3인/4인 탑승권`)의 `+` 를 매수만큼 누릅니다.
3. 결제수단·예매자 정보·필수 약관을 채우고 `valueCheck()` 가 통과하면 `reserveProc()`(결제하기 버튼과 같음)을 부릅니다.

- **알림창 가로채기** — 실행 중에는 `window.alert`·`window.confirm` 을 바꿔 끼워 창을 띄우지 않고 로그에 남기며,
  확인창은 "확인"으로 답합니다(`+` 누를 때의 탑승 인원 안내, 결제 금액 확인 등). 안내성 문구가 아닌 알림은 ⚠️ 로 표시합니다.
  끝나면 원래대로 돌려 놓습니다(결제하기 뒤에는 실패 알림을 받으려고 30초 더 유지).
- **⏰ 타이머 실행** — 응답의 `Date` 헤더로 서버 시계를 맞추고, 정한 시각 1초 전부터 20ms 간격으로 확인해 시작합니다.
  Date 헤더는 초 단위라 0.5초를 더해 오차를 ±0.5초로 맞춥니다. 숨은 탭은 타이머가 늦어지니 탭을 띄워 두어야 합니다.
- **입력값** — 예매 사이트 쪽 `localStorage`(`blPanel.cfg`)에만 저장합니다. 저장소에는 개인정보가 들어가지 않습니다.
- 한 번 실행하면 한 번만 시도합니다. 매진·실패면 이유를 남기고 멈춥니다.

- 차량번호 등 개인정보는 저장소에 커밋하지 마세요. 입력값은 브라우저에만 남습니다.
