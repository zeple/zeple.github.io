01 · Principles

설계 원칙

현재 단계에서 중요한 것은 인프라 복잡도가 아니라 데이터 품질, 추천 신뢰성, 지도 탐색 경험입니다.

1

운영 경로 최소화

Browser → Vercel → Supabase → Response. 런타임 요청에 LLM·수집 작업을 넣지 않습니다.

2

UI와 DB 분리

UI → Application Service → Repository → Supabase 경계를 유지합니다.

3

Code / AI / Human 분업

Code는 사실과 규칙, AI는 의미와 해석, Human은 최종 publish 승인을 담당합니다.

4

Raw는 절대 버리지 않기

Raw JSON은 DB 이전을 위한 임시 파일이 아니라 데이터 lineage와 rollback의 원천입니다.

5

Static / Dynamic 분리

관광지·교육·AI enrichment는 정적 파이프라인, 날씨·혼잡도 등은 런타임 context로 분리합니다.

6

확장 지점만 확보

처음부터 미래 인프라를 구현하지 않고, 필요할 때 cache·worker·recommendation service를 추가합니다.

04 · Supabase + PostGIS

Serving DB 설계

자주 검색하는 안정 필드는 컬럼으로, 아직 변화가 많은 속성은 JSONB로 둡니다.

places

create extension if not exists postgis;

create table places (
  id bigint generated by default as identity primary key,
  source text not null,
  source_id text not null,
  name text not null,
  address text,
  sido text,
  sigungu text,
  lat double precision,
  lng double precision,
  location geography(Point, 4326),
  theme_key text,
  overview text,
  attributes jsonb not null default '{}'::jsonb,
  source_updated_at timestamptz,
  published_release_id uuid,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique(source, source_id)
);

create index places_location_gix
  on places using gist(location);

place_enrichment

create table place_enrichment (
  place_id bigint primary key
    references places(id) on delete cascade,
  age_groups text[],
  stroller_friendly boolean,
  indoor boolean,
  themes text[],
  curriculum jsonb,
  confidence numeric(4,3),
  model text,
  analysis_version text,
  generated_at timestamptz,
  published_release_id uuid
);

06 · Mandatory

Raw JSON Versioning

Raw JSON은 immutable source artifact로 취급합니다. 한번 생성된 payload는 수정하지 않습니다.

권장 디렉터리

data/
├── raw/
│   ├── tour-api/
│   │   └── 2026-09-04/
│   │       └── 20260904T103000+0900/
│   │           ├── payload.json
│   │           ├── request.json
│   │           ├── metadata.json
│   │           └── sha256.txt
│   └── curriculum/
├── normalized/
│   └── <run-id>/
├── enriched/
│   └── <run-id>/
├── reports/
│   └── <run-id>/
│       ├── diff.json
│       ├── validation.json
│       └── summary.md
└── releases/
    └── vYYYY.MM.DD.N/
        ├── manifest.json
        ├── checksums.sha256
        ├── places.jsonl
        └── enrichment.jsonl

Raw 규칙

  • 생성된 raw payload는 수정 금지
  • 동일 데이터 재수집도 새 run 생성
  • request / metadata / checksum 함께 보존
  • normalized·enriched는 run-id로 분리
  • release는 immutable artifact
  • rollback은 이전 release 재-publish
Data Lineage 원본 → 정규화 → AI 분석 → 검증 → release → DB까지 어느 단계에서 데이터가 변했는지 추적할 수 있어야 합니다.
07 · Claude Code

Human-in-the-loop Data Pipeline

주 1회 또는 월 1회 개발자가 직접 실행하고, 검증된 release만 운영 DB에 반영합니다.

1. CollectRaw 응답 그대로 저장
2. NormalizeID·좌표·null·날짜 정리
3. Diffnew / changed / removed
4. Claudesemantic enrichment
5. Validate자동 + semantic 검증
6. Human Reviewwarning 확인 / 승인
7. PublishSupabase + Git tag

Collect / Normalize / Diff

npm run data:collect -- --source tour-api
npm run data:collect -- --source curriculum

npm run data:normalize -- --run <run-id>
npm run data:diff -- --run <run-id>

AI 분석은 기본적으로 new + changed만 대상으로 합니다. 전체 19,000건을 매번 재분석하지 않습니다.

08 · Validation Gate

Publish 전 안전장치

자동 Validation

  • required fields
  • unique source/source_id
  • 좌표 범위 / enum validity
  • orphan relation / JSON schema
  • duplicate / checksum
  • record count anomaly

Semantic Validation

  • 실내인데 명백한 야외 코스
  • 유모차 가능인데 장거리 등산 코스
  • source category와 테마 충돌
  • 낮은 confidence
  • 전 release 대비 대량 변경
Gate초기 권장 기준Action
삭제 비율> 전체의 2%STOP
전체 레코드 감소> 3%STOP
AI 주요 boolean 변경> 20%REVIEW REQUIRED
Validation error1건 이상STOP
09 · Claude Commands

운영 커맨드

refresh와 publish를 분리하고, publish는 항상 명시적인 사용자 승인 뒤에 수행합니다.

claude프로젝트 루트에서 Claude Code 시작
/data-refresh all diff일반적인 전체 소스 증분 갱신
/data-refresh tour-api diffTourAPI만 증분 갱신
/data-refresh all full reason=analysis-version-v3분석 버전 변경 시 전체 재분석
/data-publish v2026.09.04.1검증된 release를 명시적으로 publish

10 · Rollback

Rollback은 “수정”이 아니라 “재배포”

운영 데이터가 잘못되었을 때 수동 SQL로 값을 고치지 않습니다. 이전 검증 release를 다시 publish합니다.

/data-publish v2026.08.31.1이전 release 재배포
